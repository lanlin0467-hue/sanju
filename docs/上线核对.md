# 上线核对(任务 20)

查证日期:2026-10-08

> 以下结论供上线决策用。我不是律师;面向公众正式上线前,请你再核对一遍原文并自行确认。

## 1. OpenRouter 对上传图片 / 数据的保留规则

**结论:**

- OpenRouter 默认**不长期保存**你的提示词和回复内容;若账号打开了日志或「允许 OpenRouter 使用输入/输出」才会留存(默认关闭)。
- 经 API 提交的图片会转给所选模型服务商做推理。OpenRouter 称除路由所需外不额外持久化图片,但滥用检测、安全、计费或法律要求时可能例外。
- **模型服务商**各自的保留与训练政策不同。可用账号隐私设置或请求参数要求 Zero Data Retention(ZDR)/禁止 data collection;当前这把 Key 不是你自己的号,需请账号主人在 OpenRouter 隐私设置里打开 ZDR,并确认所用模型路由支持。
- 本站代码侧:不落盘、日志只打「收到图片 xx KB」,见 `docs/不留存图片检查.md`。

**链接:**

- https://openrouter.ai/docs/guides/privacy/data-collection
- https://openrouter.ai/privacy
- https://openrouter.ai/docs/guides/features/zdr

## 2. 大陆用户与备案 / 生成式 AI 要求

**结论:**

- 用户主要在中国大陆。若网站**向境内公众**提供生成文本服务,落入《生成式人工智能服务管理暂行办法》适用范围(见办法第二条)。
- 仅自己或很小范围内部试用、不向公众提供时,办法明确不适用「未向境内公众提供」的情形;一旦公开给不特定用户用,就要按提供者义务准备合规。
- 若服务被认定为具有舆论属性或社会动员能力,还需按要求做安全评估,并履行算法备案等手续;已上线应用还应公示所用模型与备案信息(以网信办当时要求为准)。
- 网站若放在境内服务器,通常还要单独办理 **ICP 备案**;这与生成式 AI / 算法备案不是同一件事。
- **怎么办(建议路径):**
  1. 开发与熟人内测阶段:保持非公开或限制访问,控制规模。
  2. 正式对公众开放前:换国内可备案的模型服务商、选定境内托管、咨询属地网信/律师,完成所需备案与页面公示。
  3. 继续用 OpenRouter 公网暴露给大陆用户风险高(访问不稳定 + 合规不确定),不建议作为正式方案。

**链接:**

- https://www.gov.cn/zhengce/202311/content_6917778.htm
- https://www.gov.cn/lianbo/bumen/202404/content_6943924.htm

## 3. 「本站不留存您的图片」与服务商规则是否相符

**结论:**

- **对本站而言这句话成立:** 我们不把用户图片写入服务器磁盘或日志正文。
- **对整条链路而言不够完整:** 图片仍会经过 OpenRouter 和下游模型服务商;他们不是「本站」,但用户容易理解成「任何地方都不留」。
- **怎么改(上线前建议采用):**
  - 把提示改成更准确的一句,例如:「上传图片请注意隐私与备份。本站不保存您的图片;生成时图片会发送给第三方模型服务处理,其保留规则以其公示为准。」
  - 或在页脚放简短隐私说明,链到 OpenRouter 隐私页,并请账号主人开启 ZDR。
- 在改文案之前,当前这句话只覆盖「本站」,正式上线前必须改,否则有误导风险。
