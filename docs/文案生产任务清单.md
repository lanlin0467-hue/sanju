# 文案生产工具 任务清单(v0.2)

> 对应文档:`docs/文案生产需求文档.md`(v1.0)、`docs/文案生产技术方案.md`(v0.2,方案一)
> 共 23 个任务,按编号顺序做。每个任务的依赖都指向编号更小的任务,不会遇到"依赖还没做"的情况。

## 使用说明

- **一个任务 = 一次对话 = 一次提交。** 提交信息写"任务 N:标题"。
- **命令按 macOS / Linux 终端的写法给。** 用 Windows 的话,到时我按你的系统换写法。
- **可调的数字**(字数范围、压缩上限、限流次数)统一放进一个配置文件,以后只改那一处。
- **验收是给你亲自操作的。** 按步骤点一遍、看一遍,都对了才算完成。

## 已定事项

- 用户主要在中国大陆。
- "约 20 字"定为 16–25 字(含两端),标点不计入字数。
- 隐私提示要拦截:用户点"知道了"之后才能继续选图。同一次访问只弹一次;点过"知道了"后再点"选择图片",直接打开选图。刷新页面后,下一次再弹。
- 换句次数在修改画面或心情之后、重新点"生成"时恢复为 3。只改内容、还没点"生成"时,次数不变。
- 后厨限流:同一访问者每分钟最多 3 次。每日预算:全站每天最多调用写手 4 次。

## 阶段与依赖总览

|---|---|---|
| A. 准备 | 1–3 | 搭空项目、收集样例、开通模型服务 |

## 阶段 A:准备

### 1. 搭起空项目并纳入版本管理
- **依赖**:无
- **做什么**:安装 Node.js,创建空的 Next.js(TypeScript)项目,初始化 git,做第一次提交。
- **验收**:
  1. 项目文件夹的终端里运行 `npm run dev`,不报错。
  2. 浏览器打开 `http://localhost:3000`,能看到一个页面。
  3. 运行 `git log`,至少有一条提交记录。

### 2. 收集风格样例
- **依赖**:无
- **做什么**:新建 `docs/风格样例.md`,三种风格各收集 5 句你满意的样例。样例是模仿该文风写出的句子(可以让模型试写后由你挑),**不要直接摘抄原著原句**。
- **验收**:打开 `docs/风格样例.md`,鲁迅、莎士比亚(朱生豪式)、江南(《龙族》作者)三个小标题下各至少 5 句。

### 3. 开通模型服务、拿到密钥、设消费上限
- **依赖**:无
- **做什么**:选一家在中国大陆能稳定访问、能看图、中文写得好的模型服务商,注册并拿到 API 密钥,在服务商后台设每月消费上限。密钥自己保管,不要贴进聊天或代码文件。
- **验收**:
  1. 服务商后台能看到一把可用的密钥。
  2. "消费上限 / 预算"页面能看到你设的每月上限数字。
  3. 若服务商有在线试用页:上传一张图、输入一句话,能收到回答。

## 阶段 B:后厨(后台服务)

### 4. 密钥交给项目,后厨 v0:文字进,一句话出
- **依赖**:任务 1、3
- **做什么**:把密钥放进"环境变量"文件(不提交);做 `/api/generate`,接收"心情 + 画面描述(文字)",调用一次模型,原样返回回复。**调用模型的代码集中放在一个文件里**,以后换服务商只改它。
- **验收**:
  1. 运行下面的命令,能收到一段模型回复:
     ```
     curl -X POST http://localhost:3000/api/generate -H "Content-Type: application/json" -d '{"mood":"怅然","scene":"黄昏的海边"}'
     ```
  2. 不带 `mood` 再发一次,返回明确的错误提示,不崩溃、不空白。
  3. 运行 `git status`,看不到存放密钥的文件;在所有代码文件里搜索密钥前 8 位字符,搜不到。
  4. 在项目里搜索服务商的网址,只出现在一个文件里。

### 5. 写作说明书 v1:三种风格各一句
- **依赖**:任务 2、4
- **做什么**:把"写作说明书"(提示词)单独放进一个文件,要求模型按固定格式一次返回三句:鲁迅、莎士比亚(朱生豪式)、江南。放进任务 2 的样例,并写明"模仿腔调,不要照抄原著原句"。
- **验收**:
  1. 用任务 4 的命令发"心情=怅然,画面=黄昏的海边",返回里有且只有三个字段:鲁迅、莎士比亚、江南,各是一句话。
  2. 打开写作说明书文件,能看到任务 2 的样例。
  3. 说明书只存在于这一个文件里,其他代码里没有重复的说明书文字。

### 6. 字数检查与自动重写
- **依赖**:任务 5
- **做什么**:后厨用程序数每句字数(只数汉字等文字,标点不计),不在 16–25 内就让写手重写,最多重写 1 次;重写后仍不合格的照常返回。MIN=16、MAX=25 放进配置文件。
- **验收**:
  1. 运行 `npm test`,字数检查的测试全部通过。其中包括:
     - "黄昏把海面染成了一片旧金色而风也慢了下来"(20 个汉字)→ 合格;
     - "黄昏把海面染成了一片旧金色,而风也慢了下来,我想起你。"(24 个汉字,另有 3 个标点)→ 数为 24 字,合格;
     - 只有"好"一个字 → 不合格;
     - 把第一句连写两遍(40 字)→ 不合格。
  2. 强制测试:把配置里的范围临时改成 5–6,发一次请求。运行后厨的终端里能看到类似"字数不合格,已重写 1 次"的记录,最终仍返回结果,不报错、不无限重试。测完改回 16–25。

### 7. 文风试验(10 组)
- **依赖**:任务 6
- **做什么**:准备 10 组不同的"画面 + 心情"(文字输入)全部跑一遍,结果存进 `docs/文风试验记录.md`,你逐句标"满意 / 不满意"。通过线由你定,写在表头。不满意就回到任务 5 改说明书再跑。
- **验收**:`docs/文风试验记录.md` 有 10 行,每行三句,每句都有你的标记;表头写着通过线,末行写着实际满意比例,且达到通过线。

### 8. 只换其中一种风格,并避免重复
- **依赖**:任务 6
- **做什么**:后厨支持"只换哪一种"和"之前出现过的句子"两个参数,只重写指定那一种,并要求与之前的句子不同。
- **验收**:
  1. 先发一次请求,记下三句。
  2. 再发一次,带上"只换鲁迅"和刚才那句鲁迅。
  3. 返回里**只有**鲁迅一项,且与刚才那句不同;莎士比亚、江南字段不出现。

### 9. 后厨接收图片
- **依赖**:任务 6
- **做什么**:后厨接收一张压缩后的图片,连同描述和心情一并交给写手;图片和描述至少有一项即可。附带一个试用脚本,命令类似 `npm run try -- 照片路径 心情`,方便你用自己的照片测试。
- **验收**:
  1. 用一张你自己的照片(内容明确,比如猫、咖啡杯、海边)加心情"开心",返回的三句整体上扣着照片内容。
  2. 只给图片、不给描述,能正常返回三句。
  3. 同一张图再加一句描述,三句能体现描述里的信息(你主观判断)。

### 10. 输入校验与出错处理(后厨)
- **依赖**:任务 8、9
- **做什么**:对各种坏输入和失败情况都返回清楚的中文提示,不崩溃,也不暴露密钥或内部细节。
- **验收**(逐条试):
  1. 图片和描述都没给 → 提示"请提供画面(图片或描述)"之类的话。
  2. 没给心情 → 提示缺少心情。
  3. 发一个不是图片的文件(如 PDF)→ 提示格式不对。
  4. 临时把密钥改错一位 → 提示"生成失败,请稍后再试"之类的话,不出现密钥,也不出现服务商的原始错误。试完改回。

## 阶段 C:前台(网页)

### 11. 页面骨架(手机优先)+ 必填校验
- **依赖**:任务 1
- **做什么**:做一个页面,有:选择图片按钮、画面描述输入框、心情输入框、"生成"按钮。点"生成"时检查:心情必填;画面至少有图片或描述之一;不满足就提示、不发送。暂不连后厨。
- **验收**:
  1. 用手机浏览器(或电脑浏览器调成手机尺寸)打开,四个元素都在,不用缩放、不用左右滑动就能看到全部。
  2. 在手机上点"选择图片",能调出相册或相机(此时还没有隐私提示)。
  3. 全空点"生成" → 提示缺心情和缺画面;只填心情 → 提示缺画面;只填描述 → 提示缺心情;描述和心情都填 → 没有校验提示。

### 12. 选图流程:隐私拦截、压缩、预览
- **依赖**:任务 11
- **做什么**:同一次访问里,第一次点"选择图片"时先弹出隐私提示,用户点"知道了"才打开选图;这次访问里之后再点,直接打开选图。选图后在浏览器里压小,显示预览和压缩后大小。压缩上限先用初始值 500 KB,放进配置文件,测完再调。
- **验收**:
  1. 点"选择图片":出现这句话,与你的原话一字不差(逗号是中文全角逗号):"上传图片请注意隐私与备份，本站不留存您的图片",旁边有"知道了"按钮;此时相册或选图窗口**没有**打开。
  2. 点"知道了":提示关闭,选图窗口打开。
  3. 选一张 3 MB 以上的手机原图:页面显示"压缩后 xxx KB",不超过上限,预览仍看得清内容。
  4. 选 iPhone 拍的照片也能用;若某种格式不支持,页面给提示,不白屏。选一个 PDF → 提示"请选择图片"之类的话。
  5. 点过"知道了"之后,再点"选择图片",隐私提示不再出现,直接打开选图窗口。刷新页面后,第一次再点"选择图片",提示重新出现。

### 13. 连通前台和后厨:点"生成"出三句
- **依赖**:任务 10、12
- **做什么**:点"生成"后,前台把图片、描述、心情交给后厨,显示加载中,收到结果后展示三张卡片,标明风格名。
- **验收**:
  1. 填描述"黄昏的海边"、心情"怅然",点"生成":先看到加载提示,然后出现三张卡片,分别标"鲁迅""莎士比亚""江南",各一句。
  2. 上传一张照片再生成,同样成功。
  3. 临时把后厨停掉再点"生成",页面显示友好的失败提示,不白屏、不卡死。

### 14. 复制按钮
- **依赖**:任务 13
- **做什么**:每句旁有"复制"按钮,点击后提示"已复制"。
- **验收**:在电脑浏览器里点某句的"复制",出现"已复制";粘贴到任意文本框,内容与卡片完全一致,没有多余空格、换行或风格标签。(微信里的表现留到任务 22。)

### 15. "换这句"
- **依赖**:任务 13
- **做什么**:每张卡片有"换这句",点击只更新这一张,并把之前出现过的句子交给后厨,避免重复。
- **验收**:
  1. 点鲁迅卡片的"换这句",只有鲁迅那句变,另外两张不变。
  2. 连续点几次,新句子不与前面出现过的重复。
  3. 点的过程中,这张卡片有加载状态,其他两张的"复制"仍可用。

### 16. 剩余换句次数
- **依赖**:任务 15
- **做什么**:显示"还能换 N 次",三种风格合计 3 次;用完后"换这句"不可点。用户修改画面或情绪后,要重新点"生成",次数才恢复为 3;只改内容、还没点"生成"时,次数不变。
- **验收**:
  1. 生成后显示"还能换 3 次"。
  2. 点任意卡片的"换这句"3 次(可以是不同风格,如鲁迅 1 次 + 莎士比亚 2 次),数字依次变成 2、1、0。
  3. 为 0 时,三张卡片的"换这句"都变灰不可点,页面说明原因。
  4. 换到 0 之后,只修改图片、描述或心情中的任意一项,先不点"生成":数字仍是 0,"换这句"仍然不可点。
  5. 接着点"生成",数字恢复为 3。

### 17. 手机体验打磨
- **依赖**:任务 14、16
- **做什么**:在真机上走一遍完整流程,调整排版、按钮大小、加载状态,直到顺手。
- **验收**:在你自己的手机上走完整流程:选图、填写、生成、复制、换句。全程不用缩放、不用左右滑动,按钮一次能点中,没有被键盘挡住的输入框。

## 阶段 D:上线前

### 18. 检查"不留存图片"
- **依赖**:任务 13
- **做什么**:确认后厨不会把图片写进日志或文件。我会列出项目里所有会打印请求内容的地方,逐个检查。
- **验收**:
  1. 在页面里带图生成一次,复制运行后厨终端里的全部输出,搜索"base64"或图片数据的开头特征,搜不到(最多只有类似"收到图片 xx KB"的记录)。
  2. 项目文件夹里没有新出现的图片文件。
  3. 我给你的"会打印请求内容的位置"清单里,没有任何一处会输出图片内容。

### 19. 后厨限流与每日预算
- **依赖**:任务 10
- **做什么**:按访问者限制请求频率,并设每日总调用上限。正式值写进配置文件:同一访问者每分钟最多 3 次,全站每天最多调用写手 4 次。注意:没有数据库,计数存在服务内存里,服务重启或多实例时会清零,所以这只是"尽力而为";真正的硬保险是任务 3 在服务商后台设的消费上限。
- **验收**:
  1. 打开配置文件,每分钟上限是 3,每日上限是 4。
  2. 用脚本在 1 分钟内连发 5 次:前 3 次成功,第 4、5 次返回"请求太频繁"之类的提示。这 1 分钟里成功调用写手 3 次。
  3. 等过了这一分钟,再发 1 次:成功。这是当天第 4 次成功调用。
  4. 紧接着再发 1 次:返回"今天已达上限"之类的提示。这次不再调用写手。

### 20. 上线合规核对
- **依赖**:任务 3
- **做什么**:你自己查证并记录,新建 `docs/上线核对.md`,写明三项结论和查证日期。我可以帮你找资料,结论由你确认。
  1. 所选服务商对上传图片和数据的保留规则(附链接)。
  2. 你的用户主要在大陆:备案及生成式 AI 服务的相关要求是否适用于你的网站,以及怎么办。
  3. "本站不留存您的图片"这句提示与服务商的规则是否相符;若不相符,怎么改。
- **验收**:`docs/上线核对.md` 存在,三项都有结论和日期,没有"待查"字样。

### 21. 部署到公网

  2. 在电脑浏览器里对这个页面"查看网页源代码",搜索你密钥前 8 位字符,搜不到。
  3. 线上走一遍完整流程(带图、不带图各一次),都成功。
